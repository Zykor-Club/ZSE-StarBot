# starZSEbot 服务器接入指南（自建机器人）

机器人和服务器通过 **starZSEbot 插件 + WebSocket** 连接，不需要 TShock REST API。

## 一、机器人侧（已完成部署）

机器人已监听公网 `<机器人公网IP>:10290`（NAT 转发：公网 10290 → 内网 13140）。
插件认领绑定码时通过 `GET /server/token/{6位码}` 在机器人处换取 token，再建立 WS 长连接。

> ⚠️ 如果公网 10290 访问不通（如返回 502），请检查 NAT 面板：
> 公网 `<机器人公网IP>:10290` → 内网 `<内网IP>:13140`（TCP）

## 二、TShock 服务器侧（每台服务器都要做）

### 1. 装插件
把 `starZSEbot-plugin.zip` 里的全部 DLL（保持 `ServerPlugins/` 目录结构）解压到 TShock 的 `ServerPlugins` 文件夹。
启动服务器，插件应打印：
```
[starZSEbot]您的服务器绑定码为: 123456
```

### 2. 改配置
服务器目录 `tshock/starZSEbot.json`（第一次启动后自动生成），改成：
```json
{
  "白名单开关": true,
  "服务器地址": "<机器人公网IP>:10290",
  "启用TLS": false,
  "密钥": "",
  "群OpenID": "114514",
  ...
}
```
关键字段：
- `服务器地址`：机器人公网地址和端口（注意：NAT 映射的端口，不是 22）
- `启用TLS`：自建机器人没证书，填 `false`（用 ws:// 而非 wss://）
- `白名单开关`：如果不需要白名单功能可随意，不影响绑定

改完保存，重启 TShock 或执行 `/reload`（插件已挂重载钩子，读配置）。

### 3. 群里登记
管理员在群里发（绑定码换成服务器控制台打印的 6 位数字）：
```
添加服务器 <服务器IP或域名> <游戏端口> <绑定码>
```
例：
```
添加服务器 <服务器IP> 7777 123456
```
机器人回复"登记成功，等待服务器插件认领"。

### 4. 完成绑定
插件默认每 10 秒轮询一次机器人换 token。登记后等 10 秒左右，插件控制台出现：
```
[starZSEbot]被动绑定成功!
[starZSEbot]Bot连接成功...
```
此时再在群里发 `服务器列表`，应看到 🟢 在线。

## 三、群指令

| 指令 | 作用 |
|---|---|
| 添加服务器 <ip/域名> <端口> <绑定码> | 登记一台服务器（绑定码看插件控制台） |
| 在线 | 查询本群所有服务器的在线人数 |
| 服务器列表 | 查看登记列表与连接状态（🟢在线 / 🟡已认领未连接 / ⚪等待认领） |
| 删除服务器 <序号> | 移除一台服务器（会通知插件解绑并重新生成绑定码） |

所有数据按群隔离，每个群的服务器列表互不影响。

## 四、常见问题

- **一直"等待插件认领"**：检查 starZSEbot.json 的 `服务器地址`/`启用TLS` 是否正确；确认机器人公网 10230 能访问；看插件控制台有没有反复"Bot断开连接"。
- **插件没打印绑定码**：服务器后台执行 `/zse code` 手动生成（需 starzsebot.admin 权限）。
- **解绑后重新绑定**：删除服务器后插件会自动重新生成新绑定码，控制台会打印；用新码重新登记即可。
- **服务器重启后**：插件会记住已绑定的群（密钥还在），自动重连，无需重新登记。
